# 委譲ポリシー (コピー用)

プロジェクトの `CLAUDE.md` に貼り付けてください。これを書かないと Claude は自前の `Edit` ツールを使い続けます。Claude の立場からはその方が速くて確実だからです。使うなと明示する必要があります。

以下はそのまま貼れる日本語版です。英語版は [README.md](../../README.md) にあります。どちらでも動作します — Claude はどちらの言語のポリシーも読めますし、`[i18n] language = "auto"` なら委譲の指示文の言語からローカルモデル側のプロンプト言語が決まります。

---

```markdown
# ローカル委譲ポリシー

`ollama-local` MCP サーバー経由でローカルモデルが利用できます。すべてを自分で
やるのではなく、作業をそちらに回してください。

## 委譲する

**`local_edit`** — 機械的で、仕様が明確な変更。**先にファイルを Read しないこと。**
パスは指示文の中に書き、ローカルモデルに読ませてください。
- docstring、コメント、コメントの翻訳
- 型注釈、リネーム、既に決定済みのシグネチャ変更
- ボイラープレート、テストの雛形、複数ファイルへの同一パターン適用
- フォーマットと lint の修正

**`local_explain`** — Read/Grep の代わりに、ファイルそのものではなく*事実*が必要なとき。
- 「X はどこで定義されているか」「モジュール Y は何をするか」「どの呼び出し元が Z を渡しているか」

**`local_verify`** — Bash で lint / 型チェック / テストを走らせる代わりに、
判定と失敗内容だけが必要なとき。

## 自分で処理する

- アーキテクチャと設計判断
- デバッグ、根本原因の分析
- 曖昧なもの、複数ファイルにまたがる推論が必要なもの
- セキュリティに関わるコード
- 変更内容を一段落で言い切れない編集

## ルール

- ツールが `ESCALATE` を返したら作業ツリーは変更されていません。それは自分で対応してください。
- `tier="deep"` は本当にコードの推論が必要なときだけ使ってください。数倍遅くなります。
- 委譲の 3 分の 1 以上がエスカレーションするなら、委譲する作業の種類を間違えています。
  その種類の委譲はやめてください。
```

---

## なぜこの区切り方なのか

委譲が得なのは、**Claude がファイル本文を読まずに済む場合だけ**です。委譲の指示を書くために Claude がファイルを読んでしまったら、その時点でトークンは既に消費されています。ローカルモデルに同じ作業をさせるのは、単に一段階増えただけで、何も節約していません。

だからこそ「先に Read しないこと」が箇条書きの最初に来ます。これは効率化のヒントではなく、この仕組みが成立するための前提条件です。

逆に、設計判断やデバッグを委譲してはいけない理由も同じところにあります。それらは本文の量ではなく判断の質が成果を決める作業で、7B や 30B のローカルモデルはそこで確実に劣ります。しかも検証ゲートは「構文が壊れていないか」「プロジェクトのチェックが通るか」しか見ないので、**間違ったことに成功した**編集は素通りします。

## エスカレーション率の見方

`local_status` が実測値を返します。

```
savings so far: {"calls": 41, "succeeded": 34, "escalated": 7, ...}
```

7/41 ≈ 17% は健全です。3 分の 1 を超えたら、削減量の数字より先にこちらを見てください。委譲したタスクの種類を絞るサインです。
