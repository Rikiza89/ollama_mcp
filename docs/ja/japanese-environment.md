# 日本語環境での挙動

このサーバーは実際のファイルに書き込み、実際のサブプロセスを起動し、ローカルモデルのコンテキスト予算を管理します。その 3 つはいずれも、日本語環境では英語環境と違う挙動をします。ここに書いてあるものはすべて、実際に壊れていた箇所です。

推測ではなく実測で確認したい場合は `tests/test_japanese.py` を読んでください。ここに書かれた各項目に対応するテストがあります。

---

## 1. コンソールの文字コード (cp932)

**問題だったこと。** `subprocess.run(..., text=True)` は `locale.getpreferredencoding(False)` でデコードします。日本語 Windows ではこれは cp932 です。ところが ruff、pytest、tsc、ripgrep はコンソールのコードページに関係なく UTF-8 を出力します。そのため日本語を含む出力の最初の非 ASCII バイトで `UnicodeDecodeError` が送出されていました。

これはゲートの内部で起きるうえ、誰も捕捉していませんでした。つまり「チェックが失敗する」ではなく「委譲そのものが落ちる」という挙動でした。

**現在。** サブプロセスの出力はバイト列のまま受け取り、`encoding.decode_output()` が UTF-8 → ロケールのエンコーディング → (Windows では) OEM コードページ → UTF-8 + 置換文字、の順に試します。**この関数は決して例外を投げません。** 最悪でも文字化けした文字列が返り、チェックの成否判定は終了コードに基づいて正しく行われます。

同じ処理が ripgrep の出力にも適用されます。日本語のソースファイル内のマッチは、コンソールのコードページが何であれ UTF-8 で返ってきます。

## 2. BOM 付き UTF-8

**問題だったこと。** メモ帳をはじめとする日本語 Windows のエディタは、デフォルトで BOM 付き UTF-8 を書き出します。ゲートの構文チェックはファイルを **str にデコードしてから** `ast.parse` に渡していました。先頭の U+FEFF は無条件に `SyntaxError` になります。

結果として、正しい編集がゲートに落とされ、ロールバックされ、不要なエスカレーションになっていました。しかも原因はモデルの出力ではなく、ファイルの保存形式です。

**現在。** 構文チェックは**バイト列**をそのままパーサに渡します。CPython のトークナイザは UTF-8 BOM を自前で剥がし、さらに PEP 263 のコーディング宣言（`# -*- coding: cp932 -*-`）も解釈します。JSON については `json.loads` が RFC 8259 に従って UTF-8/16/32 を自動判別しますが UTF-8 BOM だけは拒否するため、そこだけ明示的に剥がしています。

`.ollama-mcp.toml` と `package.json` も同じ扱いです。BOM 付きの設定ファイルは、もはやパースエラーになりません。

## 3. Shift-JIS のレガシーファイル

ファイルの読み書きは `errors="surrogateescape"` と `newline=""` で行われます。この組み合わせにより、**デコードできないバイト列もそのまま往復します**。つまり:

- Shift-JIS で保存された既存ファイルを編集しても、触っていない部分のバイト列は 1 バイトも変わりません。
- 改行コードは元のまま保持されます。LF のファイルが Windows 上で丸ごと CRLF に書き換わることはありません。

ローカルモデルの側からは非 UTF-8 のバイト列は文字化けして見えますが、モデルが壊した場合は構文ゲートが捕まえ、ロールバックされます。UTF-8 への変換が目的なら、それを明示的に指示してください。暗黙には決して起きません。

## 4. ファイル名の Unicode 正規化 (NFC / NFD)

**問題だったこと。** macOS はファイル名を分解済み（NFD）で保存します。一方、エディタも、他の OS も、言語モデルも、合成済み（NFC）を出力します。Mac で作られたリポジトリを Linux でチェックアウトすると、`読み込み.py` というファイルが、モデルが入力した `読み込み.py` とバイト一致しません。結果は「no such file」です。ファイルは目の前にあるのに。

**現在。** リテラルのパスが存在しない場合に限り、サンドボックスは NFC / NFD の別表記を試します。存在するファイルの解決先が勝手に変わることはなく、**これから作成する**ファイルのパスは指定されたとおりの表記を保ちます。

`[sandbox] deny` のルール照合も NFC 正規化してから比較されるため、`deny = ["設定"]` は両方の表記に対して効きます。

閉じ込めのチェックはこの補正の**前**に行われるので、別表記の探索がワークスペースの外に出ることはありません。

## 5. トークンの数え方

**問題だったこと。** 「4 文字で 1 トークン」は英語ソースの比率です。日本語はおおむね 1 文字で 1 トークンです。これが 2 か所に影響していました。

1. **削減量の表示。** `local_status` の `estimated_tokens_avoided` が、日本語のファイルで実際の約 3 分の 1 を報告していました。委譲が最も効くリポジトリで、委譲しない理由を示す数字が出ていたことになります。
2. **ローカルモデルのコンテキスト。** ツール実行結果の上限は 20,000 **文字**でした。日本語ではこれは約 20,000 トークンです。fast ティアの `num_ctx` は 16,384 なので、Ollama が**黙って**切り捨て、モデルは全体を見ていないファイルを編集していました。

**現在。** `encoding.estimate_tokens()` が文字種ごとに数えます（ASCII は 4 文字/トークン、CJK は 1 文字/トークン、その他の非 ASCII は 2 文字/トークン）。ツール実行結果には文字数と**トークン数**の両方の上限がかかり、先に達した方が効きます。

これはあくまで推定であり、表示される箇所すべてで推定値として明示されています。

## 6. DONE / ESCALATE の判定

**問題だったこと。** ループの終了判定は `text.upper().startswith("ESCALATE")` でした。日本語で指示すればモデルは日本語で答えます。`エスカレート: 対象のファイルが見つかりません` はこの条件に一致せず、**回答**として扱われていました。

作業ツリーは変更されていないのに、レシートは成功を報告する。このサーバーが起こしうる最悪の誤りです。

**現在。** `sentinels.py` が判定を担当します。キーワードは日英両対応（`DONE` / `完了`、`ESCALATE` / `エスカレート` / `エスカレーション`）、区切り文字には全角コロンを含み、`**DONE:**` のような Markdown の装飾も剥がしてから照合します。`DONEISH` のようにキーワードで始まるだけの語は一致しません。

プロンプト側は、日本語プロンプトであっても ASCII のキーワードを使うよう明示的に要求します。上記はそれを無視するモデル（7B はよく無視します）のための安全網です。

## 7. 標準エラー出力

MCP のトランスポートは stdin/stdout を UTF-8 に固定しますが、stderr はプラットフォームのエンコーディングのままです。cp932 のコンソールでは、非 ASCII のパスや日本語の指示を含むトレースバックが、エラーハンドラの内部から `UnicodeEncodeError` を投げてサーバーごと落とします。

`server.main()` は起動時に stderr を `errors="replace"` で再構成します。ログ行が文字化けすることはあっても、サーバーが落ちることはありません。

## 設定

```toml
[i18n]
language = "auto"   # "auto" | "en" | "ja"
```

環境変数 `OLLAMA_MCP_LANG` が設定ファイルより優先されます。

`auto` は呼び出しごとに指示文から判定し、判定できなければマシンのロケール（`LC_ALL`、`LC_MESSAGES`、`LANG`、`LANGUAGE`、`locale.getlocale()`）を見ます。

現在どう解決されているかは `local_status` が表示します。

```
言語: ja (from auto)
```

## 翻訳されないもの

`APPLIED`、`NOT APPLIED`、`ESCALATE`、`PASS`、`FAIL`、および `gate:` / `local:` のキー。

これらはプロトコルであって文章ではありません。公開されている `CLAUDE.md` の委譲ポリシーはどれも「ツールが ESCALATE を返したら作業ツリーは変更されていない」と書いています。このトークンを訳せば、それらが静かに壊れます。翻訳されるのは周囲の説明文だけです。
